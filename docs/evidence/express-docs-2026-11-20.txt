Scale to zero When an instance is idle, it scales down to zero compute so you aren't billed for compute during periods of inactivity. When the instance receives a new connection or query, it resumes operation in approximately 20 seconds.

Connectivity AlloyDB Express supports the following types of connectivity: Private Service Connect: connects to your instance from your Virtual Private Cloud (VPC) network through Private Service Connect endpoints, without exposing the database to the public internet. Public DNS: connects to your instance from clients outside of your VPC network. Public IP isn't supported; instead, AlloyDB Express provides external connectivity through public DNS. You can also connect to AlloyDB Express instances using the AlloyDB Auth Proxy and AlloyDB Language Connectors for Go, Python, and Java. Automatic storage growth Storage for AlloyDB Express instances scales automatically as your data grows, up to 20 GB, and you're billed only for the storage that you use. When storage reaches 20 GB, further write operations aren't allowed.

The following list describes how each resource in AlloyDB Express differs from AlloyDB: Cluster: a top-level container for your databases, logs, and metadata in a Google Cloud region. Unlike an AlloyDB cluster, an AlloyDB Express cluster doesn't support cross-region replication or backups. Instance: the access point that provides connection details for your applications. Unlike an AlloyDB cluster, which can contain a regional HA primary instance and multiple read pool instances, an AlloyDB Express cluster contains a single zonal primary instance that handles both reads and writes. Node: the virtual machine (VM) that runs the database engine. An AlloyDB Express instance runs on a single node with either 1 vCPU (4 GB RAM) or 2 vCPUs (8 GB RAM) and has no standby node, which helps minimize costs. Pricing AlloyDB Express offers usage-based pricing for compute and storage and includes a monthly free tier. The following list describes how AlloyDB Express bills for usage: Free tier: each month includes 50 compute units and 2 GB of storage per billing account for the first 12 months. Usage beyond the free tier is billed on 1 vCPU or 2 vCPU instances, representing 1 compute unit and 2 compute units respectively. Compute: compute is billed per second, based on compute units with a 1:4 vCPU-to-memory ratio. You aren't billed for compute while the instance is idle. Storage: storage is billed for the amount that you use, not for provisioned capacity, up to the 20 GB maximum. Storage is billed while the instance is active or idle. Discounts: standard enterprise discounts apply. CUDs aren't available. For more information, see AlloyDB pricing .

Supported regions AlloyDB Express supports the following regions: asia-east1 asia-east2 asia-northeast1 asia-southeast1 australia-southeast1 europe-west2 us-west1

Limitations AlloyDB Express has the following limitations: PostgreSQL version support: AlloyDB Express supports PostgreSQL 18 only. Compute and instance configuration: AlloyDB Express supports a single zonal primary instance with 1 vCPU (4 GB RAM) or 2 vCPUs (8 GB RAM). Read pool instances, regional HA, and cross-region replication aren't supported. Storage limit: AlloyDB Express supports up to 20 GB of storage. When storage reaches 20 GB, further write operations aren't allowed. Maximum connections ( max_connections flag): the max_connections database flag is fixed at 200 to help prevent out-of-memory (OOM) issues. Modifying the max_connections flag has no effect on an AlloyDB Express instance. PostgreSQL extensions: you can load all PostgreSQL extensions supported by AlloyDB , but memory-intensive extensions can cause OOM issues if they exceed the instance's 4 GB or 8 GB memory limit. To help prevent OOM issues, AlloyDB Express enforces the following fixed extension settings, which scale memory usage and turn off columnar engine advisor recommendations: google_plan_management extension: the google_plan_management.managed_plans_pool_size_in_mb flag is set to 10 . google_columnar_engine and google_db_advisor extensions: the google_columnar_engine.memory_size_in_mb flag is set to 400 , the google_columnar_engine.enable_auto_columnarization flag is set to false , and the google_db_advisor.enable_columnar_advisor flag is set to false . Backups and disaster recovery: automated backups, on-demand backups, PITR, and Backup and DR aren't supported. Security: CMEK isn't supported. Interfaces: Terraform and Config Connector aren't supported. Billing and SLA: CUDs don't apply, and AlloyDB Express isn't covered by an SLA. Upgrade path: after you upgrade an AlloyDB Express cluster to AlloyDB, you can't downgrade it back to AlloyDB Express.
